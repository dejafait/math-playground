# Circuit counting as a lower bound for MCSP decision time

Tested 2026-09-25. The proposal was to use the scarcity of small circuits, and the resulting almost universal high circuit complexity of represented functions, to prove that deciding circuit size from an explicit truth table needs superpolynomial time.

**WHY IT FAILS.** [L006](../lemmas/L006-mcsp-counting-versus-decision.md) separates the represented function's r-bit input from the MCSP input containing its N=2^r-bit truth table. Counting gives circuit size Omega(N/log N) for almost every represented function, while every such function has an O(N log N)-gate construction; these are polynomial scales in the table length. More decisively against density alone, MCSP with thresholds up to Theta(log N/log log N) has an exact polynomial-time enumeration algorithm and a NO fraction at least 1-N^3/2^N. The Shannon-hard functions are among these easy-to-reject instances for large r. This rejects the bare counting-to-decision-hardness inference, not general MCSP hardness, all uses of counting, or recognition mechanisms involving additional structure. The high-threshold uniform-distribution error bound for the constant answer NO is explicitly not exact worst-case recognition.
