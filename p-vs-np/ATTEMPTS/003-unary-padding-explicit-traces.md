# Unary padding as a repair for explicit computation certificates

Tested 2026-09-25. The proposal was to enlarge the input enough that an explicit rejecting computation fits one fixed polynomial certificate bound, while retaining a clocked diagonal disagreement against every polynomial-time decider.

**WHY IT FAILS.** [L003](../lemmas/L003-unary-padding-diagonalization.md) separates the two length conventions. When the simulated machine receives the same full padded input, deliberately slow polynomial-time rejectors produce yes-instances whose actual transcripts exceed every fixed polynomial bound in that full length. Padding increases their running time as well as the certificate budget. When the simulated machine instead receives only the shorter core and the padding pays for its core-based clock, the resulting language has a uniform polynomial-time decider: complementing the answer on the core does not force disagreement on the padded input. This refutes this explicit-transcript repair, not all padding arguments or other certificate systems. The full-input language is outside P but is not shown to belong to NP, and the slow rejectors themselves decide an easy constant language.
