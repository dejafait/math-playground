## Reopened primary execution cases

Official rolling documentation was labeled Python 3.15.1 when read
2026-10-24; step-440's manifest records 3.15.0. Record the actual later
interpreter; documentation is not a binary attestation.

- [Execution model 4.2.1–2](https://docs.python.org/3/reference/executionmodel.html#binding-of-names): loop targets bind names; module bindings are global, while function scope and enclosing closures isolate local bindings absent directives.
- [compile](https://docs.python.org/3/builtins/functions.html#compile): flags=0, dont_inherit=True and optimize=0 retain assertions; invalid full source raises. AST parsing alone is insufficient.
- [exec](https://docs.python.org/3/builtins/functions.html#exec): a single fresh globals dictionary also serves as locals; separate dictionaries have class-body visibility consequences. Restricted builtins alone are not a security boundary; the explicit AST/call whitelist remains required.
- [subprocess.run](https://docs.python.org/3/library/subprocess.html#subprocess.run): completion is waited for; timeout kills and waits, with process-creation delay qualification. Require observed child exits.
- [monotonic](https://docs.python.org/3/library/time.html#time.monotonic): use differences; the macOS clock is shared across processes. [setitimer](https://docs.python.org/3/library/signal.html#signal.setitimer) clears on zero; [handler execution](https://docs.python.org/3/library/signal.html#execution-of-python-signal-handlers) can be delayed by C calculations. An armed timer does not guarantee hard dispatch.

These cases justify the particular controls, not universal software
correctness. Only execution semantics were reopened externally.
