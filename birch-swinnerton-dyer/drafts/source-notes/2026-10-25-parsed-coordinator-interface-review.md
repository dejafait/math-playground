## Primary API evidence and limits

Read the official Python documentation served as version 3.15.1:
[AST node locations](https://docs.python.org/3/library/ast.html#ast.AST),
[If](https://docs.python.org/3/library/ast.html#ast.If),
[parse](https://docs.python.org/3/library/ast.html#ast.parse), and
[unparse](https://docs.python.org/3/library/ast.html#ast.unparse).
`elif` is an `If` in `orelse`; positions use UTF-8 byte columns, with
optional end positions. Parsing alone does not guarantee compilability.
Unparsing need not preserve original text. These contracts support
structural selection and bounded source splicing, not whole-source
regeneration or a runtime guarantee.

Also inspected [TokenInfo](https://docs.python.org/3/library/tokenize.html#tokenize.TokenInfo)
and [untokenize](https://docs.python.org/3/library/tokenize.html#tokenize.untokenize):
token columns count Unicode code points, whereas reconstruction guarantees
token types/text but can change spacing. Tokenizer regeneration is
therefore unsuitable for the unchanged-byte requirement. Tokenization is
not an essential input to the approved mechanism. Served documentation
version does not identify the future executing interpreter.
