## Proposed rewrite procedure after approval

1. Freeze writes and record exact local/remote branch tips, tags and refs. Make a verified external Git bundle/mirror before rewriting; record old-to-new commit and path mappings. Check collaborator forks/branches and coordinate the cutover.
2. Build a path-retention manifest: for every artifact considered for removal, identify its canonical proof/script references and independent audit/provenance use. Keep proof certificates, verifier inputs, source snapshots and consequential failure evidence in the repository regardless of reproducibility or size. Remove only explicitly classified disposable data; do not treat JSON or regenerability as a disposal criterion. The ignore proposal is not authorization to erase evidence.
3. Rewrite in an isolated disposable clone, not the active research workspace. Insert the approved root .gitignore in the initial commit; replay the remaining commits in dependency order. Reconcile the later .gitignore additions so they do not overwrite the approved initial policy. Gitignore alone does not remove a tracked file or a historical blob: explicitly filter only approved paths, and never feed broad extensions to a destructive history filter without the retention manifest.
4. Split the four confirmed mixed commits at exact paths/hunks. Policy/runner/checker/ignore changes get descriptive feature/maintenance commits with required migrations; independent mathematical work retains progress titles. Relabel other commits only where replay inspection establishes a mismatch. Existing narrow, coherent agent commits are not assumed perfect: 33803bec is explicitly on the split list.
5. Verify each meaningful infrastructure boundary with its appropriate offline tests and structural checks. Preserve historical dependency/toolchain constraints. Compare the final rewritten tree with the original except for explicitly approved removals and ignore-policy changes; verify retained certificates and source references. Do not repair the historical mathematics incidentally while splitting commits.
6. Review old/new mappings, branch refs, final tree and storage measurements. Publishing rewritten main requires a separate explicit approval after the concrete rewritten branch is reviewable. If approved, use a guarded force-with-lease against the recorded remote tip, never an unguarded force. Preserve the external backup and publish contributor resynchronization instructions.

## Storage findings and limits

At the audited tip, the tracked tree has 14,720 files and about 128.9 MB of uncompressed file content. Reachable historical blob contents total about 132.9 MB (each reachable blob counted once). Large examples include a 29.4 MB forced-v verifier input text file, 5.36/5.09 MB Laguerre certificates and partially generated startup TSV/binary files. These are candidates for review, not automatic deletion: several are load-bearing evidence.

Local git count-objects reported 2.87 GiB of packed storage. This is not the same quantity as reachable blob size or a GitHub clone measurement: packs can include other/ref-log-retained/unreachable objects and structural/delta overhead. No garbage collection, pruning or cleanup was attempted, and no remote-size savings are promised.

The revised proposal keeps all proof evidence versioned by default, including JSON/text/binary certificates at legacy paths. It adds workstation/environment/build-cache exclusions and former-provider runtime directories, and reserves .generated/, .scratch/, .run-logs/ and .cache/ for explicitly disposable work. It does not ignore by calculation-file extension or blanket output-*/step-* names. Future organized topics can use tracked certificates/, inputs/, fixtures/ and reports/ alongside ignored temporary work areas. Existing paths need not move merely to remain versioned.

This revision supersedes the earlier literal-filter estimate of 79.6 MB: that estimate excluded mathematical certificates and is not the size target for the revised policy. No numerical shrinkage is promised until disposable paths are explicitly classified. The tracked evidence/layout policy is detailed in [proof-evidence-storage.md](proof-evidence-storage.md). The active .gitignore remains unchanged pending application of the proposed policy; no history filtering or certificate relocation has occurred.

Do not confuse this plan with current work: startup overview compaction and its regression guard are ordinary additive maintenance commits, not a history rewrite.
